# Toffee Roller — план по фазам

Веб-панель для охоты за floating IP из белых подсетей Selectel. Всё управление —
на сайте: ключи, прокси, подсети, пойманные IP, история, метрики. Telegram — только
уведомления (поймал IP, аварии, входы в панель).

**Отдельный проект.** С toffee VPN не связан: свой репозиторий, свой бот, своя база,
свой сервер. От сайта toffee взята только эстетика (тёплая тёмная палитра, Geist,
градиентные акценты) — код и токены скопированы и живут здесь самостоятельно,
ничего не импортируется из VPN-репозитория.

Принципы:
- **Всё в базе.** Никаких `.env` с аккаунтами, json-файлов состояния и txt-списков.
  В env только то, без чего сервер не стартует (ключ шифрования, путь к БД, порт).
- **Всё на лету.** Добавил ключ / прокси / подсеть, поменял настройки — движок
  подхватывает сразу, без перезапуска чего-либо. Страница обновляется сама (SSE).
- **Безопасно по умолчанию.** Секреты зашифрованы, вход защищён, пойманный IP
  никогда не удаляется автоматически.
- **Красиво.** Каждый экран проходит дизайн-проверку: ровная сетка, понятные статусы,
  адаптив до 375 px, пустые состояния и скелетоны вместо «пусто/загрузка».

## Что было (разбор старого SelectelRoller)

| Модуль | Судьба |
|---|---|
| `scanner/client.py` — клиент Selectel/OpenStack, прокси, ретраи | **ядро движка**, переносится в `backend/app/engine/selectel.py` |
| `scanner/hunt.py` — прицельная охота, классификация ошибок, ротация прокси-сессий | логика переносится в `KeyWorker` |
| `scanner/whitelist.py`, `models.py`, `telegram.py`, `resell.py` | переносятся частично |
| `main.py`, `dual.py`, `dashboard.py`, `rich_ui.py`, `strategy.py`, `ip_frequency.py`, `bootstrap.py`, `setup_wizard.py`, `prompts.py`, `config.py`, `paths.py`, `state.py`, `run.*`, `docs/`, старый README | **удалены** (старый случайный перебор + терминальный UI) |
| `whitelist*.txt`, `.env`, `temp/*.json` | однократный импорт в БД (фаза 2), дальше не используются |
| `tools/rumap_to_whitelist.py` | остаётся в `tools/` |

Опыт прода, который обязан пережить переписывание:
- темп не быстрее 10 с между запросами / 30 с между кругами — иначе Selectel даёт
  `403 rule:create_floatingip` = бан **аккаунта**;
- `ConnectTimeout` на эндпоинте региона = бан **IP** → лечится прокси;
- proxxxymiron: страна `_country-RU` и липкая сессия `_session-<id ≥ 8>` в **пароле**;
  мёртвая сессия (TLS WRONG_VERSION_NUMBER / DECODE_ERROR, SOCKS `Malformed reply`) →
  ротация `g1, g2…`; сбой в одном регионе — бан эндпоинта, ротация не нужна;
- `403 PolicyNotAuthorized` на конкретный `floating_ip_address` — политика, цель отключается.

## Архитектура

```
toffee-roller/
├── backend/                 Python 3.12+, FastAPI, SQLAlchemy 2 (async), Alembic
│   └── app/
│       ├── core/            настройки env, шифрование, логирование
│       ├── db/              модели, сессия, миграции
│       ├── auth/            вход, 2FA, сессии, защита от перебора
│       ├── engine/          selectel.py (клиент), worker.py, manager.py, proxy.py
│       ├── metrics/         сбор и агрегация метрик
│       ├── checks/          проверка пойманных IP (bsboard)
│       ├── notify/          Telegram
│       ├── bus.py           шина событий → SSE
│       └── api/             REST + /api/stream (SSE)
├── web/                     Next.js 16, React 19, Tailwind 4, Radix, motion, Phosphor
├── tools/                   rumap_to_whitelist.py
└── docker-compose.yml       backend + web (+ caddy на проде)
```

- **БД — SQLite (WAL)** в одном файле `data/roller.db`. Пишет один процесс, объёмы
  маленькие; бэкап = копия файла. SQLAlchemy позволяет переехать на Postgres
  сменой `DATABASE_URL`, если понадобится.
- **Один процесс backend** держит API и движок. Каждый включённый ключ — asyncio-задача
  `KeyWorker`. `WorkerManager` сверяет «что включено в БД» с «что запущено» после
  каждого изменения через API (reconcile) — так всё применяется на лету.
- **Настройки** живут в БД, в памяти держится копия; сохранение в API обновляет копию,
  воркеры читают значения на каждом шаге — новая пауза действует со следующего запроса.
- **Шина событий**: всё, что происходит (журнал, статус ключа, поимка, метрика),
  публикуется в `bus` → пишется в БД → уходит в браузер по SSE.
- **Фронт ходит к backend через свой же origin** (`/api/*` проксируется Next.js), cookie
  `httpOnly; Secure; SameSite=Strict`.

| Таблица | Главное |
|---|---|

| `sessions` | token_hash, admin_id, ip, user_agent, created_at, last_seen_at, expires_at, revoked |
| `login_attempts` | ts, ip, login, ok, reason (журнал входов, основа для блокировки) |
| `selectel_keys` | name, account_id, auth_type (service_user / token), username, password_enc, token_enc, project_id/name, enabled, status (`starting / hunting / paused / sleeping / error / banned / auth_failed / done`), status_reason, proxy_mode (auto / fixed / none), proxy_id, proxy_session_gen, ip_goal, current_round, current_target, attempts_total, caught_total, consecutive_errors, last_ok_at |
| `proxies` | url_enc, label, kind (http / socks5), status (ok / partial / dead / unchecked), exit_ip, exit_country, latency_ms, regions_ok, checked_at, last_error |
| `subnets` | cidr, region (определяется по пулам Selectel), white_count, enabled, source (import / manual), note, caught_total |
| `hunt_targets` | key_id, subnet_id, region, network_id, os_subnet_id, kind (exact / partial), disabled_reason, attempts, full, errors |
| `caught_ips` | ip, region, key_id, subnet_id, floating_ip_id, caught_at, protected, on_account, released_at, check_status, check_payload, checked_at, note |
| `events` | ts, level, kind, key_id, region, message, data (json) — журнал |
| `metric_points` | bucket (минута), key_id, region, attempts, busy_409, errors, timeouts, proxy_errors, caught, avg_latency_ms |
| `audit_log` | ts, admin_id, ip, action, target, details — кто что менял в панели |
| `settings` | одна строка json: паузы, длинная пауза, IP на ключ, таймаут, порог ошибок, регионы, уведомления, tg chat_id, bsboard-ключ (enc) |
